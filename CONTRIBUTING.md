# Как поучаствовать

Спасибо за интерес! Правки, баг-репорты и идеи приветствуются — от опечатки в
README до новых инструментов MCP.

## Коротко

1. Форкните репозиторий и создайте ветку от `main`.
2. Внесите правки, добавьте тесты, прогоните `pytest` и `ruff check .`.
3. Откройте pull request. В `main` напрямую не пушит никто, включая мейнтейнера —
   всё идёт через PR и ревью.

## Окружение

```bash
git clone https://github.com/<ваш-логин>/winelab-mcp
cd winelab-mcp
uv venv && uv pip install -e ".[dev]"

pytest                      # оффлайн, сеть подменена httpx.MockTransport
ruff check . && ruff format --check .
```

Нужен Python 3.10+. CI гоняет Linux, macOS и Windows на 3.10–3.14 — если правка
завязана на ОС (пути, права на файлы, кодировки), проверьте это в тестах.

## Тесты

Правило простое: **PR без тестов не проходит ревью**, если он меняет поведение.

* Обычные тесты не ходят в сеть. Фейковый сайт живёт в `tests/conftest.py`
  (`FakeSite`) — добавьте туда ответ нужного эндпоинта и покройте свой код.
* Тесты не должны трогать сессию пользователя: фикстура `store` перенаправляет
  файл во временный каталог. Не пишите в `~` из тестов.
* `tests/test_live.py` ходит в настоящий winelab.ru и запускается только с
  `WINELAB_LIVE=1`. Туда добавляют **проверки-канарейки**: они ловят момент,
  когда сайт сломает недокументированный API. Живые тесты только читают —
  не отправляйте SMS, не кладите товары в чужую корзину, не логиньтесь.
* `tests/test_protocol.py` поднимает сервер подпроцессом и проверяет
  рукопожатие MCP. Новый инструмент добавьте в `EXPECTED_TOOLS`.

## Стиль

* `ruff` — единственный арбитр по форматированию и импортам, настройки в
  `pyproject.toml`. Отдельных обсуждений про стиль не ведём.
* Комментарии и docstring'и — по-русски, как и весь остальной код.
* Docstring инструмента MCP читает языковая модель. Пишите в нём, **когда**
  инструмент применять и что означают параметры, а не пересказ сигнатуры.
* Инструменты возвращают словарь и не бросают исключения наружу: ошибка — это
  `{"ok": False, "error_kind": ..., "error": ...}`. Так модель может объяснить
  проблему пользователю, а не упасть.

## Про реверс-инжиниринг API

Сервер работает поверх недокументированных эндпоинтов winelab.ru
(см. [API.md](API.md)). Если вы нашли новый эндпоинт или старый переехал:

* опишите его в `API.md` — метод, путь, параметры, формат ответа и что именно
  не работает (сайт щедр на `405` и HTML вместо JSON);
* добавьте канарейку в `tests/test_live.py`;
* не добавляйте ничего, что обходит антибот Qrator, эмулирует нескольких
  пользователей или создаёт нагрузку. Сервер должен вести себя как один
  человек с одним браузером.

Не принимаются: массовый парсинг каталога, скликивание, автоматическое
оформление заказов, работа с чужими аккаунтами.

## Безопасность

Здесь ходят куки сессии и коды из SMS. В логи, в ответы инструментов и в тесты
не должны попадать пароли, коды и содержимое `session.json`. Нашли уязвимость —
не открывайте публичный issue, см. [SECURITY.md](SECURITY.md).

## Коммиты и PR

* Заголовок коммита — по-русски, в повелительном наклонении, до ~70 символов.
  В теле — **почему**, а не пересказ диффа.
* Одна тема на PR. Рефакторинг «заодно» лучше отдельным PR — его проще ревьюить.
* В описании PR расскажите, как проверяли: какие тесты, ходили ли на живой сайт.
* CI должен быть зелёным. Джоба «Канарейка API winelab.ru» может падать из-за
  чужого сайта — она информационная и мерж не блокирует.

Ревью делает мейнтейнер. Если неделю тихо — смело пингуйте в PR, это не грубость.
